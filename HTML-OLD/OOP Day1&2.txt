
C Vs C++ 
================
1- Paradigm:
C: 
C is a procedural language. It focuses on functions and procedures that operate on data. 
C programs are generally written as a series of function calls that manipulate data, often organized in a sequence.
C++: 
C++ is multi-paradigm, supporting both procedural and object-oriented programming (OOP). 
This means it allows you to write code using objects, classes, inheritance, polymorphism, and other OOP principles. 
This makes C++ a more versatile language in terms of design.

How Objects Are Created:
=============================
Automatic (Local Objects):
1. Objects can be created automatically when declared as local variables in functions.
When a local object goes out of scope, its destructor is automatically called to clean up the memory.
MyClass obj; 
		       ===================================
2. Dynamic Memory Allocation:
Objects can be created on the heap (dynamic memory) using the new operator (in languages like C++, Java, and others). These objects remain in memory until they are explicitly destroyed using the delete operator or garbage collection (in some languages like Java and Python).
 MyClass* obj = new MyClass(); 
 			===================================
3.Using Factory Methods (in more complex designs):
In some OOP designs, objects are created using factory methods or factory classes. These are specialized methods that abstract the process of creating objects. The programmer can call the factory method instead of directly using a constructor.
class MyClass {
public:
    int x;
    MyClass() { x = 30; }  // Constructor
    static MyClass * createObject() {
        return new MyClass();  // Factory method creating the object
    }
};

int main() {
    MyClass* obj = MyClass::createObject();  // Object created via factory method
    std::cout << obj->x;  // Output: 30
    delete obj;
    return 0;
}

Destructor (wish for something before I die)
=================================================
- it is aSpecial Function.called when object destroyed.
- destructor is the same as the class name, but preceded by a tilde (~).
- No Parameters
- No Return any Value (not even void).
- A class can only have one destructor.(Can't Overloaded).
- Destructors are used to clean up resources when an object is destroyed.
- They are automatically called when an object goes out of scope or is deleted.

~ className(){
}
====================================================================================
Purpose of a Destructor:
=============================
Resource Deallocation: Destructors are used to release resources (like memory, file handles, network connections) that were allocated by the object during its lifetime.
Clean-Up: They ensure that the class does any necessary clean-up before the object is destroyed, preventing memory leaks or other resource-related issues.


Destructor Rules:
======================
Can’t be overloaded: Unlike constructors, there can be only one destructor per class.
Automatic invocation: It is automatically called when an object is deleted or goes out of scope.
Order of calling: In case of inheritance, the destructor of the derived class is called first, followed by the destructor of the base class.



Notes :-
- The constructor dynamically allocates memory (new int) for ptr and initializes it with the value passed to the constructor.
- The destructor frees the dynamically allocated memory (delete ptr) to avoid memory leaks.
- When the object obj goes out of scope at the end of the main() function, the destructor is automatically invoked, cleaning up the memory.
- Destructors are critical for preventing memory leaks and ensuring proper resource management in object-oriented programs.

Static Members 
1. shared attributes among all objects from this class.
2. its lifetime is the application lifetime
3. can be accessed from class name or any object [if it public]
4. has constant value.
5. must be initialized
6. can be private or public.
7. can be used in all class functions

Static members are not part of the object, so they are not initialized by constructors.
Shared among all instances of the class.
Exists independently of any object of the class.
Memory for the static attribute is allocated only once, during the lifetime of the program.

Use Cases for Static Private Attributes
    Global Counters: Keep track of the number of objects created or some other global statistic related to the class.
    Shared Configuration:Store class-wide configuration values (e.g., a database connection or log level) accessible to all instances but private to the class.
 
 
 
 
 
 
 Example :- 
 ==============
 
class Database {
private:
    // Static attributes for shared configuration
    static string host;
    static string user;
    static string password;

public:
    // Static methods to set configuration
    static void setConfig(const string& dbHost, const string& dbUser, const string& dbPassword) {
        host = dbHost;
        user = dbUser;
        password = dbPassword;
    }

    // Static methods to get configuration
    static void printConfig() {
        cout << "Database Configuration:" << endl;
        cout << "Host: " << host << endl;
        cout << "User: " << user << endl;
        cout << "Password: " << password << endl;
    }

    // Simulate a database connection
    static void connect() {
        cout << "Connecting to database at " << host << " with user " << user << endl;
        // Here, you would add actual database connection logic
    }
};

// Definition of static attributes
string Database::host = "localhost";
string Database::user = "root";
string Database::password = "root";

int main() {
    // Default configuration
    Database::printConfig();

    // Update configuration
    Database::setConfig("127.0.0.1", "admin", "admin123");

    // Print updated configuration
    Database::printConfig();

    // Connect to the database
    Database::connect();

    return 0;
}


Advantages of Static Shared Configuration
1. Consistency:
     All instances share the same database configuration, reducing redundancy and ensuring consistency.
2. Ease of Access:
     No need to create an instance of the class to access or modify the configuration.
3. Encapsulation:
     The configuration is encapsulated within the class, providing a single point of control.
4. Resource Efficiency:
     A single shared resource (e.g., database connection) reduces memory usage and avoids multiple connections.

Considerations and Enhancements
1. Thread Safety:
    If the application is multi-threaded, use synchronization mechanisms 
    (e.g., std::mutex) to prevent race conditions when accessing or modifying 
    static attributes.

static std::mutex configMutex;
static void setConfig(const string& dbHost, const string& dbUser, const string& dbPassword) {
    std::lock_guard<std::mutex> lock(configMutex);
    host = dbHost;
    user = dbUser;
    password = dbPassword;
}

2.Singleton Pattern:
    Combine the shared configuration with a singleton pattern to manage a single database connection instance.

3. Error Handling:
    Validate the configuration and handle connection errors gracefully.
4. Configuration Persistence:
    Store the configuration in an external file (e.g., JSON, XML) and load it dynamically.

1. Constant Methods                                           
ReturnType MethodName(Arguments) const;
- Constant methods can only call other constant methods within the class.

Purpose
Ensures the method cannot modify any member variables of the object.
Guarantees that the method is safe to call on constant objects
                      ====================================================
2. Constant Objects
- A constant object is an instance of a class that cannot be modified after its initialization. 
const object ==> Call only Const Function 
const ClassName objectName(parameters);
Behavior
=========
Only constant methods can be called on a constant object.
Any attempt to call a non-constant method or modify a member variable results in a compile-time error.
                       ====================================================
Feature	    :           Constant Method	                                Constant Object
Declaration	:    Add const after the method signature.	     : Use const before the object declaration.
Restriction	:    Cannot modify member variables.	         : Only constant methods can be called on it.
Access	    :    Can be called on const & non-const objects. : Restricted to calling constant methods only.
Example	    :    void func() const;	                         : const ClassName obj;
                        ====================================================

When to Use Constant Methods and Objects
====================================================
Use constant methods to guarantee that a method will not alter the object's state.
Use constant objects when you want to ensure immutability of an object.

Notes:- 
Constant Member Variables
A constant member variable must be initialized at the time of object construction and cannot be modified afterward.
        class Example {
            private:
                const int value; // Constant member variable
            public:
                // Constructor initializes the constant member
                Example(int v) : value(v) {}
                int getValue() const {
                    return value;
                }
        };
Mutable Variables in Constant Methods
If a member variable is declared with the mutable keyword, it can be modified even in a constant method or constant object.
    class Example {
        private:
            int value;
            mutable int accessCount; // Mutable variable

        public:
            Example(int v) : value(v), accessCount(0) {}

            int getValue() const {
                accessCount++; // Allowed because accessCount is mutable
                return value;
            }
    };

Best Practices to Avoid Dynamic Area Problems
===================================================
1. Implement the Rule of Three (or Five)
    If your class manages dynamic memory, explicitly define the:
        Destructor
        Copy Constructor
        Copy Assignment Operator
    Optionally include:
        Move Constructor
        Move Assignment Operator (for efficiency).

2. Avoid Unnecessary Copies
Pass large objects by reference instead of value (const T&) when possible.
