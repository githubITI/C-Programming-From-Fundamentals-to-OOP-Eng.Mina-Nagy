Code Reusability and Inheritance:

  • Reusing code often requires copying and modifying existing functions, leading to code duplication.
  • Example:
void drawCircle(int x, int y, int radius) { /*...*/ }
void drawSquare(int x, int y, int side) { /*...*/ }

Difficulty in Managing Complexity:

  • As programs grow in size, managing complexity becomes challenging since the relationships between data and functions become less clear.

  • Example:

    • A large procedural codebase may have many functions tightly integrated, making understanding and modifying it difficult.

How OOP Solved These Problems

Encapsulation:

  • OOP packages data and methods that operate on the data into a single unit called a class, shielding the internal state from outside interference.

  • Example:

        class Counter {
    private:
        int count;
    public:
        Counter() : count(0) {}
        void increment() { count++; }
        int getCount() const { return count; }
    };

    int main() {
        Counter c;
        c.increment();
        printf("%d\n", c.getCount()); // Output: 1
    }

Loose Coupling via Inheritance and Polymorphism:

  • OOP allows you to create new classes that inherit properties and behavior from existing classes, promoting code reuse and reducing duplication.
  • Example:
    class Shape {
    public:
        virtual void draw() = 0; // Pure virtual function
    };

    class Circle : public Shape {
    public:
        void draw() override {
            printf("Drawing Circle\n");
        }
    };

    class Square : public Shape {
    public:
        void draw() override {
            printf("Drawing Square\n");
        }
    };

Improved Code Reusability:

  • OOP promotes creating libraries of classes that can be reused across various projects, enabling developers to build on existing code rather than duplicating efforts.

  • Example:

        // Both Circle and Square classes can be reused wherever shapes are needed
    Shape *shapes[2];
    shapes[0] = new Circle();
    shapes[1] = new Square();
    for (int i = 0; i < 2; i++) {
        shapes[i]->draw();
    }

Managing Complexity with Abstraction:

  • OOP supports abstraction, allowing you to simplify complex systems by modeling real-world entities and their relationships, making the code easier to maintain.

  • Example:

        class Employee {
    private:
        std::string name;

    public:
        Employee(const std::string &name) : name(name) {}
        void showDetails() {
            printf("Employee Name: %s\n", name.c_str());
        }
    };

    int main() {
        Employee emp("Alice");
        emp.showDetails(); // Output: Employee Name: Alice
    }

Summary

In summary, procedural programming struggles with issues such as global state management, tight coupling, code duplication, and complexity management. OOP addresses these problems with principles like encapsulation, inheritance, polymorphism, and abstraction, enabling more manageable, reusable, and scalable code. By organizing code effectively and promoting reuse, OOP helps developers create robust applications.

5️⃣ Problem: Hard to Extend Without Breaking Existing Code

Hard to Extend Code Safely → OOP Polymorphism

Procedural programming is fragile.
  • When you add new features, many functions break.
  • If you add a new Shape type, you must modify ALL functions.
drawCircle()
drawSquare()
drawTriangle()  <-- must be added everywhere

C (manual switching)

void drawCircle();
void drawSquare();

void draw(int type){
    if(type == 1) drawCircle();
    else if(type == 2) drawSquare();
}
✔ OOP Solution: Polymorphism
  • Allows adding new functionality without modifying existing code.
       Shape (abstract)
          draw()
      /      |       \
 Circle   Square    Triangle
 draw()   draw()     draw()
  • Example:
class Shape {
public:
    virtual void draw() = 0;
};

class Circle : public Shape {
    void draw() override { cout << "Circle"; }
};

class Square : public Shape {
    void draw() override { cout << "Square"; }
};
  • A function can work with any shape:
void render(Shape* s){
    s->draw(); // Works for new shapes too
}
  • Now adding Triangle doesn’t break existing code.
  • You can add Rectangle without touching old code.
