1) What is the implicit object parameter?

  • For a non-static member function
struct Car {    
int speed;    
void moveBack() { 
    speed -= 10; 
    }
}

a call like:

Car c;
c.moveBack();

is conceptually transformed by the compiler into something equivalent to:

Car* const this = &c;   // implicit object parameter
// inside moveBack():
this->speed -= 10;

  • this is a pointer to the object you called the method on.

  • It is implicit—you don’t write it in the parameter list, but you can use it inside the function as this.

  • this is non-null for well-formed calls and const (you cannot reseat this to point elsewhere).

  • Static member functions do not have an implicit object parameter; they behave like free functions scoped inside the class.

2) How cv-qualifiers change the implicit parameter (const, volatile)

  • The type of the implicit parameter depends on the function’s qualifiers: struct S { void f(); // S* const this void g() const; // const S* const this void h() volatile; // volatile S* const this void i() const volatile; // const volatile S* const this };

  • If a function is const, you cannot modify the object inside (only call other const functions).

  • Attempting to change members in a const function will cause a compile error (unless the member is mutable).

3) Ref-qualifiers (& and &&) on member functions

  • From C++11+, you can qualify member functions with lvalue (&) or rvalue (&&) ref-qualifiers. They constrain which objects can call them, and change the implicit parameter to:
S& (for &) or
S&& (for &&),

conceptually applied to *this.

struct Box {
    std::string data;
    std::string&& consume() && {       // callable only on rvalues
        return std::move(data);
    }
    const std::string& view() const & { // callable only on lvalues
        return data;
    }
};
Box makeBox();
Box b;
makeBox().consume();  // OK: rvalue Box
b.consume();          // ERROR: requires rvalue (use std::move(b).consume())
b.view();             // OK: lvalue object
std::move(b).view();  // ERROR: requires lvalue; view() is const &

This is crucial for designing APIs that move from temporaries but don’t accidentally move from named variables.

4) How overload resolution uses the implicit object parameter

When you write:

obj.method();

  • the compiler picks an overload whose implicit object parameter type matches obj’s value category and qualifiers:

    • const object → prefers const member functions.
    • lvalue object → prefers &-qualified functions.
    • rvalue temporary → can select &&-qualified function.

  • Example:

struct T {
    void foo() &        { /* lvalue object */ }
    void foo() &&       { /* rvalue object */ }
    void foo() const &  { /* const lvalue object */ }
};

T t;
t.foo();           // calls foo() &
std::move(t).foo(); // calls foo() &&
const T ct;
ct.foo();          // calls foo() const &

5) Why your free-function vs member-function calls differ

  • Free functions that take an object parameter:
void moveBack(Car& c) { 
    c.speed -= 10; 
}
moveBack(c);

Explicit parameter; you control passing by reference (Car&) or value (Car).

  • Member functions use the implicit this:
struct Car { int speed; void moveBack() { speed -= 10; } };
c.moveBack();  // implicitly passes &c to the function as 'thi
  • If you declared void moveBack(Car c); as a free function, calling moveBack(c); would copy the car and modify the copy. Using Car& (reference) avoids copying.
  1. Calling syntax sugar and equivalence
  • These are equivalent (conceptually):
c.moveBack();
// ~ roughly equivalent to:
Car::moveBack(&c); // pseudo-syntax; actual function has implicit 'this'

For const objects:

const Car c{10};
// c.moveBack(); // ERROR: moveBack() must be const to be callable on const object

struct Car {
    int speed;
    void moveBack() const { /* cannot modify speed here */ }
};

7) Returning *this (fluent interfaces)

Because this is a pointer, *this is the object. You can return it (by reference) to chain calls:


struct Accumulator {
    int v = 0;
    Accumulator& add(int x) { v += x; return *this; }
    Accumulator& sub(int x) { v -= x; return *this; }
};

Accumulator a;
a.add(10).sub(3).add(5); // chaining via returned reference
  • Make sure the return type matches your intended value category (&, const&, or && for builders returning temporaries).

8) Explicit control with static and free functions

  • Static member functions have no implicit object parameter:
struct Util {    
    static void log(const char* msg) {
         std::cout << msg << "\n"; 
         }
};
Util::log("hello");  // called without an objectShow more lines
  • Free functions are great when behavior doesn’t conceptually belong to a single object or you want symmetric APIs:
void collide(Car& a, Car& b) { /* uses both */ }

9) Advanced: const-correctness and mutable

If you need to modify logical state in a const function (e.g., a cache), mark the member mutable:

struct Cache {
    mutable bool filled = false;
    mutable int value = 0;

    int get() const {
        if (!filled) { value = compute(); filled = true; }
        return value;
    }
};

This allows writes in const functions only to mutable members.

10) Putting it all together (mini example)

#include <iostream>
#include <string>
#include <utility>

struct Car {
    int speed = 0;
    std::string name;

    // lvalue-qualified: only lvalues can call
    void moveBack() & { speed -= 10; }

    // rvalue-qualified: only temporaries or std::move can call
    void moveForward() && { speed += 10; }

    // const-qualified: callable on const objects, read-only
    void print() const { std::cout << name << "@" << speed << "\n"; }

    // fluent API: return *this
    Car& setName(std::string n) & { name = std::move(n); return *this; }
};

int main() {
    Car c;
    c.setName("mina").moveBack(); // OK: lvalue object

    Car temp;
    std::move(temp).moveForward(); // OK: rvalue-qualified member

    const Car cc{20, "constCar"};
    cc.print();                    // OK: const member function

    // Free function comparison:
    auto moveBackFree = Car& car { car.speed -= 10; };
    moveBackFree(c);               // modifies via explicit ref
}

TL;DR

  • The implicit object parameter is the hidden this pointer passed to non-static member functions.

  • Its type changes with function qualifiers:

    • void f() → S* const this
    • void f() const → const S* const this
    • void f() & → lvalue-qualified (S&)
    • void f() && → rvalue-qualified (S&&)

  • Use qualifiers to control which objects can call a function and to enforce const-correctness and move behavior.

  • For modifying external objects via free functions, pass by reference (T&) rather than by value.
