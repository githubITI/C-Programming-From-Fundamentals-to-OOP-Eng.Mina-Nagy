Parameter vs Argument

  • Parameter = the variable name inside the function.
  • Argument = the value you pass to the function.
  1. Parameters
    • Parameters are variables listed in a function’s definition.
    • They are placeholders for the values the function will receive.
          def add(a, b):   # a and b are PARAMETERS
        return a + b
    • Here, a and b are parameters.
  2. Arguments
    • Arguments are the actual values passed to the function when it is called.
    • Example:
          result = add(5, 3)   # 5 and 3 are ARGUMENTS
    • Here, 5 and 3 are arguments.
Parameter Argument
Variable in the function definition Actual value passed to the function

Early Return

  • What is Early Return?
    • Instead of nesting multiple conditions, you exit the function as soon as you know you don’t need to continue.
1. Input Validation
//✔ Avoids unnecessary computation.
int divide(int a, int b) {
    if (b == 0) return -1; // Early return for invalid input
    return a / b;
}
2. Error Handling

bool processFile(const std::string &path) {
    if (!fileExists(path)) return false; // Early exit if file missing
    // Continue processing...
    return true;
}
3. Guard Clauses
void processData(Data *data) {    
  if (data == nullptr) return; // Guard clause   
   // Safe to use data now
}
4. Avoid Deep Nesting
  • Without early return:
void func() {
    if (condition1) {
        if (condition2) {
            if (condition3) {
                // Do work
            }
        }
    }
}
  • With early return:
void func() {
    if (!condition1) return;
    if (!condition2) return;
    if (!condition3) return;
    // Do work
}

✔ Much cleaner and easier to read.

Best Practices
  • Use early return for invalid states or quick exits.
  • Do not overuse it in large functions—too many returns can reduce clarity.
  • Combine with meaningful error codes or exceptions in C++

Global Variables

Are Global Variables Good or Bad in C/C++?
  • ❌ Generally: Global Variables are Considered BAD Practice
  • Most C/C++ developers avoid global variables because:
    1. Hard to debug
    • Any function can change the global variable → you don’t know where the change happened.
    1. Hidden dependencies
    • A function looks simple, but secretly depends on a global variable.
    1. Breaks modular programming
    • Functions become less reusable because they rely on global data.
    1. Naming conflicts
    • Globals increase the chance of variable name collisions, especially in large programs.
    1. Multi-thread issues
    • If two threads access a global variable → race conditions and unpredictable behavior.
Golden Rule in C/C++

✔ Use local variables whenever possible ✔ Use global variables only when truly necessary ❌ Avoid modifying global variables inside many functions

Do You HAVE to Use a Global Variable with an ISR?
Why Do We Usually Need a Global Variable with an ISR?

  1. An ISR cannot receive arguments

        void __interrupt() ISR(void)

    • No parameters

    • No way to pass data into the ISR

    • So if the ISR needs to access or update some data → it must use a global variable.

  2. An ISR cannot return values

    int ISR(void) { return 5; }   // ❌ impossible
    • So the only way for an ISR to "send" data to main() is:

  3. Local variables in main() are NOT visible to the ISR

        int main() {
        int count = 0;   // local variable
    }

    void __interrupt() ISR() {
        count++;         // ❌ ISR cannot access this
    }
    • Local variables live only inside their function → ISR cannot see or modify them.
⭐ Correct Communication Method
    volatile int flag = 0;  // global + volatile
    /*
        volatile is a type qualifier that tells the compiler:
        👉 "Do NOT optimize this variable. Its value can change at any time."
        Normally, the compiler may optimize code to make it faster.
        But with volatile, you tell the compiler:
        ❗ “Always read the variable from memory. Never trust a cached value.”
    */
    void __interrupt() ISR() {
        flag = 1;           // ISR updates it
    }

    int main() {
        while (1) {
            if (flag) {
                // handle interrupt event
                flag = 0;
            }
        }
    }
Are there alternatives instead of global variables ?
  • Yes, but they are rare and only work in special environments.
1.static inside the ISR
  • You can store data only for the ISR itself:
void __interrupt() ISR() {
    static int counter = 0;
    counter++;
}
  • But main() CANNOT access this → So this does NOT replace global variables.
2. Using an RTOS (e.g., FreeRTOS)

  • You can use:

    • queues
    • semaphores
    • event flags

  • But internally, these still use shared memory (similar to globals).

  • So the concept is the same.

3. Hardware registers
  • Sometimes the ISR writes to a hardware memory address: (volatile uint32_t)0x40001000 = 1;
  • But this is not useful for normal programs.
