What is polymorphism (in C terms)?

  • Polymorphism means “same interface, different implementations.” In C, you typically implement it with:

    • Dynamic polymorphism → via function pointers and vtable-like structs (runtime dispatch).

    • Static polymorphism → via macros or C11 _Generic (compile-time dispatch).

1) Dynamic Polymorphism with Function Pointers (VTable Pattern)

You create a struct of function pointers (a “vtable”), and each “type” provides its own implementations.

  • Example: Shapes with area() and draw()

    • What’s happening?

      • Each concrete type (Circle/Rectangle) sets its vptr to its own function table.

      • Calls like s->vptr->area(s) dynamically dispatch to the right implementation.

    • Pros: Flexible, idiomatic in C projects (OS kernels, embedded).

    • Cons: Manual boilerplate; no type safety across casts without care.

          #include <stdio.h>
    #include <math.h>
    /* Forward declarations */
    typedef struct Shape Shape;
    /* VTable type: the "interface" */
    typedef struct {
        double (*area)(const Shape *self);
        void   (*draw)(const Shape *self);
    } ShapeVTable;
    /* Base Shape: holds a pointer to its vtable */
    struct Shape {
        const ShapeVTable *vptr;
        // Common data could go here
    };
    /* ---- Circle implementation ---- */
    typedef struct {
        Shape base;   // "inherits" Shape
        double r;
    } Circle;
    double circle_area(const Shape *self) {
        const Circle *c = (const Circle *)self;
        return M_PI * c->r * c->r;
    }
    void circle_draw(const Shape *self) {
        const Circle *c = (const Circle *)self;
        printf("Drawing Circle (r=%.2f)\n", c->r);
    }
    const ShapeVTable Circle_vtbl = {
        .area = circle_area,
        .draw = circle_draw
    };
    void Circle_init(Circle *c, double r) {
        c->base.vptr = &Circle_vtbl;
        c->r = r;
    }

    /* ---- Rectangle implementation ---- */
    typedef struct {
        Shape base;
        double w, h;
    } Rectangle;

    double rect_area(const Shape *self) {
        const Rectangle *r = (const Rectangle *)self;
        return r->w * r->h;
    }
    void rect_draw(const Shape *self) {
        const Rectangle *r = (const Rectangle *)self;
        printf("Drawing Rectangle (%.2f x %.2f)\n", r->w, r->h);
    }
    const ShapeVTable Rectangle_vtbl = {
        .area = rect_area,
        .draw = rect_draw
    };
    void Rectangle_init(Rectangle *r, double w, double h) {
        r->base.vptr = &Rectangle_vtbl;
        r->w = w; r->h = h;
    }

    /* ---- Client code: uses the common interface ---- */
    void render_and_report(const Shape *s) {
        s->vptr->draw(s);
        printf("Area = %.2f\n", s->vptr->area(s));
    }

    int main(void) {
        Circle c; Rectangle r;
        Circle_init(&c, 3.0);
        Rectangle_init(&r, 4.0, 5.0);

        Shape *shapes[] = { (Shape*)&c, (Shape*)&r };
        for (size_t i = 0; i < 2; ++i) {
            render_and_report(shapes[i]); // dynamic dispatch via vtable
        }
        return 0;
    }

2) Callbacks & Function Pointers (Common in C APIs)

  • Polymorphism can be as simple as passing a function pointer to a generic algorithm.
  • Example: qsort-style comparator
  • Same interface, different behavior: you swap in different comparators.
#include <stdio.h>
#include <stdlib.h>

int cmp_int(const void *a, const void *b) {
    int x = *(const int*)a, y = *(const int*)b;
    return (x > y) - (x < y);
}
int cmp_desc(const void *a, const void *b) {
    int x = *(const int*)a, y = *(const int*)b;
    return (y > x) - (y < x);
}

int main(void) {
    int arr[] = {5, 2, 9, 1};
    size_t n = sizeof arr / sizeof arr[0];

    qsort(arr, n, sizeof(int), cmp_int);   // ascending
    // qsort(arr, n, sizeof(int), cmp_desc); // descending

    for (size_t i = 0; i < n; ++i) printf("%d ", arr[i]);
    puts("");
    return 0;
}

3) Static Polymorphism with C11 _Generic

This is compile-time selection based on the expression’s type.

#include <stdio.h>

#define to_string(x) _Generic((x), \
    int:        to_string_int,     \
    double:     to_string_double,  \
    const char*: to_string_cstr,   \
    default:    to_string_unknown  \
)(x)

const char* to_string_int(int v) { static char buf[32]; snprintf(buf, sizeof buf, "int=%d", v); return buf; }
const char* to_string_double(double v) { static char buf[32]; snprintf(buf, sizeof buf, "double=%.2f", v); return buf; }
const char* to_string_cstr(const char* s) { return s; }
const char* to_string_unknown(...) { return "unknown"; }

int main(void) {
    printf("%s\n", to_string(42));
    printf("%s\n", to_string(3.14));
    printf("%s\n", to_string("hello"));
}

Pros: Zero runtime overhead; type-safe selection. Cons: Limited; doesn’t do inheritance or runtime dispatch.

4) Other Techniques

  • Void pointers (void*) + size arguments: Generic containers or algorithms; be careful with casting.
  • Unions: Hold multiple possible types; pair with an enum “tag” to know which is active.
  • Macros: Generate type-specific code; powerful but harder to debug.
  • Struct embedding: Simulate inheritance by placing a “base” struct at the start of a derived struct (as in the vtable example).

When to use which?

  • Callbacks / function pointers: When you need flexible behavior injection (e.g., I/O handlers, strategies).

  • Vtables: When modeling a family of types with common operations (drivers, GUI widgets, protocol layers).

  • _Generic: When compile-time specialization is enough (type-based printing, math helpers).

  • void* + size: When building generic containers (lists, vectors) or mimicking templates.

Pitfalls & Tips

  • Casting safety: Always cast carefully when up/down-casting between base and derived structs.

  • Lifetime & ownership: Clearly define who allocates/frees objects; consider init/destroy functions in the vtable.

  • Const-correctness: Use const for functions that don’t mutate the object.

  • Error handling: Include error-return conventions in the vtable (e.g., int (*open)(...) returning status codes).

  • ABI stability: If you change vtable layout, recompile all users.
